# Love Bank

Fortnightly check-in tracker for David and Beth: each rates the ten emotional needs from *His Needs, Her Needs* (how much it matters, how it's going), picks a top five and writes short notes.
Each need also has an optional "why" comment (stored in `notes.why` as need→text) so the other person can see what sits behind a gap. The page shows each person's love bank balance over time, per-need gaps, where to focus next, and the full history. Built 2026-11-06, moved off a Claude artifact the same day.

## Fondness, a little each day

A 35-day exercise (seven themed weeks, five days each): one thought to carry around and one small thing to do, each person on their own. It has a panel on the tracker and its own screen. The idea of a daily fondness and admiration practice comes from John and Julie Gottman's work; the prompts in `index.html` (`FOND`, `FOND_WEEKS`) are original, not theirs, and the day numbers match the Gottman sheet's layout (week N, day M) if you want to follow that alongside. Progress and answers live in `public.love_bank_fondness` (one row per person per day) via `love_bank_fondness_list` and `love_bank_fondness_save`. The list returns everyone's progress but written answers only for the person asking; since the password is shared, that's a courtesy, not a lock. "Done, and send" also posts the answer to Love notes.

## What's underneath

A guided conversation for a disagreement that keeps coming back: name it, one person talks about what it means to them (tapping themes that fit) while the other only asks questions, the listener writes back what they heard and the speaker confirms, then they swap. It ends with a summary and an optional "what you understand better now"; it is not meant to settle the issue. Taking turns as speaker and listener on a stuck issue comes from John and Julie Gottman's work; the wording, questions and themes in `index.html` (`U_THEMES`, `U_QUESTIONS`) are original. Conversations are stored in `public.love_bank_under` (issue, date, and a `data` object with each person's themes and what the other heard) via `love_bank_under_list`, `love_bank_under_save` and `love_bank_under_delete`.

## After an argument

A guided repair conversation for once both people have calmed down, in five steps: how it felt (each taps feelings), how each saw it (one describes, the other writes the part that makes sense and the speaker ticks "I feel understood"), what it touched (sore spots and where they come from), my part (what set me up, an apology, and the other's reply), and next time (one thing each will do and one thing each asks). It ends with a summary. The method of working back through a fight in steps comes from John and Julie Gottman's work; the wording and lists in `index.html` (`RP_FEEL`, `RP_SORE`, `RP_SETUP`) are original. Conversations are stored in `public.love_bank_repair` via `love_bank_repair_list`, `love_bank_repair_save` and `love_bank_repair_delete`; chip choices are saved as their text.

## Love notes

A message thread between the two of you ("Love notes" in the header): text, quick emoji, photos and memes. Each phone is asked once who's using it (localStorage `love-bank-me`). Notes live in `public.love_bank_notes`; pictures are shrunk on the phone (JPEG, max 1600 px) or kept as-is for GIFs up to 3 MB, and stored inline as data URLs, fetched one at a time. Functions: `love_bank_notes_list`, `love_bank_note_send`, `love_bank_note_image`, `love_bank_notes_read` (marks the other person's notes seen), `love_bank_note_delete` (own notes only). The thread polls every 8 seconds while open and every minute otherwise.

### Alerts (Web Push)

- `sw.js` (service worker, no caching) shows the alert and opens `./#notes` when it's tapped.
- In Love notes, "Turn on alerts" asks permission, subscribes with the server's VAPID public key, and saves the subscription via `love_bank_push_subscribe` into `public.love_bank_push_subs` (one row per phone, with whose phone it is). On iPhone this only works from the Home Screen app (iOS 16.4+).
- A trigger on `love_bank_notes` (`love_bank_notes_alert`) calls the `love-bank-push` edge function through pg_net, authenticated by `hook_secret` in `public.love_bank_push_config`. The function encrypts and sends the alert to the other person's phones and drops subscriptions Apple reports as gone.
- The VAPID key pair was generated by the edge function on first use and lives only in `love_bank_push_config`. Source: `supabase/functions/love-bank-push/` (deployed with JWT verification off; it checks the hook secret or a Love Bank session itself).

## On the phone

The site is an installable web app (`manifest.webmanifest`, icons in `icons/`). On iPhone: open the site in Safari, Share → Add to Home Screen. It opens full-screen with its own icon. The home-screen app keeps its own storage, so enter the password once inside it. Changes pushed to `main` reach the installed app too.

## Talk it through

A date-night view (header button "Talk it through"): one need per screen with both people's latest numbers, their "why" comments, generated questions for each to ask the other, and a "What we'll try" box. Agreements autosave to `public.love_bank_talks` (one row per date, `notes` = need→text) via `love_bank_talks_list` / `love_bank_talk_save`, and the latest talk shows on the tracker as "What we agreed". A shortlist for the evening is stored in the same row as `notes._plan` (ordered need keys); a talk with a plan but nothing agreed carries over to the day it's used.

### Recording a talk

Talk it through can record the conversation on one phone (tick "We've both agreed", then Start recording). Each screen becomes its own audio clip (cut every 5 minutes at most), sent as it finishes to the `love-bank-talk-ai` edge function, which passes it to OpenAI (`gpt-transcribe`) and returns only the text. Audio is never stored. The text waits on that phone (localStorage `love-bank-talk-transcript-<date>`) until the wrap-up screen, where "Write it up" sends it with each need's ratings to Claude (`claude-opus-5-5`, structured JSON output) and shows an editable draft: an overall note, and for each need what was talked about and a next step. Saving writes them to the talk row (`notes._overall`, `notes._summary`, and the per-need next steps) and deletes the transcript from the phone.

The function needs two secrets, set in Supabase → Edge Functions → Secrets: `OPENAI_API_KEY` and `ANTHROPIC_API_KEY`. Without them the Record panel says recording isn't set up. Source: `supabase/functions/love-bank-talk-ai/` (`ai.ts` holds the prompt and the request logic). The phone must stay unlocked while recording; if the screen turns off, recording pauses.

## Password gate

- One common password, no user accounts. Its bcrypt hash lives in `public.love_bank_secret` (single row).
- `love_bank_login(p_password)` returns a random session token (or null for a wrong password). Only the token's SHA-256 is stored, in `love_bank_sessions`; sessions lapse after 180 days unused. The page keeps the token in localStorage (`love-bank-session`), so each device stays signed in.
- All reads/writes go through `love_bank_list`, `love_bank_save`, `love_bank_delete`, `love_bank_talks_list`, `love_bank_talk_save` and the love-notes functions (all require a valid token). `love_bank_logout` ends one session. No table is granted to `anon`/`authenticated`; verified that direct table reads and `love_bank_set_password` are refused from the web.
- Brute-force limit: after 10 wrong passwords in 15 minutes (counted in `love_bank_attempts`) logins are refused until the window passes.
- **Set or change the password** in the Supabase dashboard → family-finance → SQL Editor:
  `select public.love_bank_set_password('the new password');`
  This also signs out every device. The function is not callable through the API. Don't save that query as a snippet.

## Updating

Edit `index.html`, commit, push to `main`. Pages redeploys in about a minute.

## Balance formula

For each need with both ratings: sum(matters × going) / sum(matters × 10) × 100.
